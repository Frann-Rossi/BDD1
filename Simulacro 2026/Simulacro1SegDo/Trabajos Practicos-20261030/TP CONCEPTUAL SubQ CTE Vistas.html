Trabajo Práctico Conceptual

Subconsultas · CTE · Vistas

Análisis, elección de alternativas y justificación
El objetivo no es escribir consultas extensas, sino decidir qué recurso resulta más conveniente en cada situación.

Objetivo: analizar diferentes situaciones de consulta y decidir qué recurso de SQL resulta más adecuado en cada caso. En varias situaciones puede existir más de una solución técnicamente válida; por eso interesa especialmente la justificación de la decisión.

Antes de mostrar cada propuesta

  • Leer la situación completa.
  • Decidir qué alternativa utilizarías.
  • Pensar brevemente por qué la elegirías.
  • Recién después presionar Mostrar propuesta de resolución.
SITUACIONES DE ANÁLISIS

Situación 1

Un sistema genera un informe con información de clientes y sus compras. Para construirlo primero se deben identificar determinados clientes según varios criterios. Ese mismo conjunto de clientes será utilizado posteriormente en dos partes diferentes de una misma consulta.

Una primera propuesta consiste en repetir la lógica de selección cada vez que sea necesaria.

¿Qué alternativa propondrías?
Pensá tu elección y su justificación antes de mostrar la propuesta.

Elección sugerida: CTE

Una alternativa conveniente sería definir una sola vez el conjunto de clientes y asignarle un nombre para poder reutilizarlo dentro de la misma sentencia.

WITH clientes_seleccionados AS ( SELECT ... FROM cliente WHERE ... ) SELECT ... FROM clientes_seleccionados JOIN ...;

¿Por qué? Una subconsulta podría resolver el problema, pero repetir la misma lógica varias veces complica lectura y mantenimiento. Una vista tampoco parece necesaria si ese conjunto solo tiene utilidad durante esta sentencia.

Situación 2

Se encuentra la siguiente estructura dentro de una consulta:

SELECT p.nombre, p.precio FROM producto p WHERE p.id_categoria IN ( SELECT c.id_categoria FROM categoria c WHERE c.estado = 'ACTIVA' );

Un integrante del equipo propone reemplazar la parte interna por una CTE para que la consulta quede “más moderna”.

¿Qué alternativa propondrías? ¿Mantendrías la estructura actual o realizarías el cambio?
No toda consulta auxiliar necesita convertirse en otro recurso.

Elección sugerida: mantener la subconsulta

La consulta interna es breve, aparece una sola vez y cumple una función clara dentro de la condición.

Convertirla en CTE sería posible, pero no necesariamente mejora la solución. El hecho de que una herramienta exista no obliga a utilizarla cuando la estructura actual ya expresa correctamente la intención.

Situación 3

Una empresa posee un informe utilizado por Administración, Ventas y Gerencia. El informe reúne información proveniente de varias tablas y contiene diferentes condiciones de negocio.

Actualmente cada aplicación contiene una copia propia de esa consulta. Cuando una condición cambia, hay que modificarla en distintos lugares.

¿Qué alternativa propondrías?
Pensá especialmente en el alcance que debería tener la solución.

Elección sugerida: vista

En este escenario conviene considerar una vista porque la misma lógica debe quedar disponible para diferentes consultas y aplicaciones.

CREATE VIEW informe_clientes AS SELECT ... FROM cliente JOIN ... WHERE ...;

Una CTE o una subconsulta podrían formar parte de una consulta puntual, pero habría que volver a escribir su lógica en cada sentencia donde se necesitara.

Situación 4

Un desarrollador escribe:

SELECT nombre FROM cliente WHERE id_cliente IN ( SELECT id_cliente FROM venta WHERE total > 200000 );

Otro desarrollador propone crear una vista llamada clientes_ventas_altas y utilizarla en la consulta. La consulta se ejecutará únicamente desde este informe y no se prevé utilizar ese resultado en otros procesos.

¿Qué alternativa propondrías?
Evaluá si agregar un objeto permanente realmente aporta algo en este caso.

Elección sugerida: mantener la subconsulta

Crear una vista sería técnicamente posible, pero introduciría un objeto permanente en la base para resolver una necesidad puntual.

La vista tendría más sentido si existiera una necesidad real de reutilización, encapsulación o acceso frecuente a esa lógica.

Situación 5

Una consulta debe realizar los siguientes pasos:

  • obtener las ventas agrupadas por vendedor;
  • calcular el total vendido por cada uno;
  • calcular otro resultado utilizando esos totales;
  • combinar ese resultado con información de empleados;
  • finalmente aplicar distintas condiciones.

La versión actual contiene varios niveles de consultas anidadas.

¿Qué alternativa propondrías para organizar la solución?
No es necesario escribir la consulta completa. Pensá en la estructura general.

Elección sugerida: varias CTE

La consulta representa naturalmente una secuencia de etapas. Cada resultado puede recibir un nombre y utilizarse en el paso siguiente.

WITH ventas_vendedor AS ( SELECT ... ), resumen AS ( SELECT ... FROM ventas_vendedor ) SELECT ... FROM resumen JOIN empleado ...;

También podría resolverse mediante subconsultas anidadas, pero la lectura probablemente sería más difícil. Una vista tendría sentido solo si alguno de esos resultados necesitara reutilizarse fuera de esta consulta.

Situación 6

Existe la siguiente definición:

CREATE VIEW pedidos_pendientes AS SELECT id_pedido, id_cliente, fecha FROM pedido WHERE estado = 'PENDIENTE';

A las 10:00 se realiza una consulta y aparecen 18 pedidos. Luego se modifican algunos registros de la tabla pedido. A las 11:00 se ejecuta nuevamente:

SELECT * FROM pedidos_pendientes;
¿Qué esperarías que ocurra? No respondas solamente “cambia” o “no cambia”: explicá de qué depende.
Pensá qué relación existe entre la definición consultada y los datos actuales de sus tablas de origen.

Propuesta de análisis

El resultado puede ser diferente. Si algunos pedidos dejaron de tener estado PENDIENTE, ya no deberían aparecer; si surgieron nuevos pedidos pendientes, podrían incorporarse.

La definición permite reutilizar una lógica de consulta, pero el resultado depende del estado actual de las tablas involucradas.

Situación 7

Se debe mostrar información de proveedores. Para una única columna del resultado se necesita obtener un dato relacionado mediante otra consulta. La lógica necesaria es pequeña y solamente se utiliza en ese lugar.

¿Qué alternativa propondrías?
La solución más sofisticada no siempre es la más adecuada.

Elección sugerida: subconsulta

Una subconsulta puede ser la alternativa más directa si el dato auxiliar se utiliza una sola vez, la lógica es breve y su ubicación dentro de la consulta es clara.

SELECT p.nombre, ( SELECT ... FROM ... WHERE ... ) AS dato_adicional FROM proveedor p;

No existe una ventaja automática por transformar este caso en una CTE o en una vista.

Situación 8

Dos desarrolladores resuelven el mismo requerimiento.

Alternativa A

SELECT * FROM ( SELECT ... FROM venta GROUP BY ... ) AS resumen WHERE ...;

Alternativa B

WITH resumen AS ( SELECT ... FROM venta GROUP BY ... ) SELECT * FROM resumen WHERE ...;

Ambas consultas producen el mismo resultado.

¿Cuál elegirías? Justificá la decisión.
Acá no alcanza con decidir cuál “funciona”. Las dos funcionan.

Propuesta de análisis

Las dos alternativas son válidas. Si el bloque interno es pequeño y se utiliza una sola vez, la subconsulta derivada puede ser suficiente.

Si ese bloque representa una etapa importante del razonamiento, la consulta seguirá creciendo o el resultado se utilizará varias veces dentro de la sentencia, la CTE puede hacer más clara la intención.

La elección no depende únicamente de qué recurso puede resolver el problema, sino también de cómo se comunica y mantiene la solución.

Situación 9

Un equipo crea una vista para mostrar determinadas operaciones comerciales:

CREATE VIEW operaciones_importantes AS SELECT ... FROM operacion WHERE ...;

Tiempo después surge un informe que necesita trabajar únicamente con algunas filas de esa vista y además realizar otros cálculos temporales.

Un integrante del equipo sostiene que, como ya se utiliza una vista, no debería utilizarse una CTE ni una subconsulta.

¿Qué opinás?
Pensá si los tres recursos son excluyentes entre sí.

Propuesta de análisis

La afirmación no es correcta. Una vista puede actuar como origen de datos dentro de otra consulta y combinarse con CTE o subconsultas.

WITH seleccion AS ( SELECT ... FROM operaciones_importantes WHERE ... ) SELECT ... FROM seleccion;

Cada recurso puede resolver una necesidad distinta dentro de una misma solución.

Situación 10

Una consulta funciona correctamente pero contiene cuatro subconsultas anidadas. El equipo decide reemplazarlas automáticamente por cuatro CTE porque considera que una consulta con CTE siempre es mejor.

¿Estás de acuerdo?
Evitá responder solamente “sí” o “no”. ¿Qué deberías analizar antes?

Propuesta de análisis

No necesariamente. La cantidad de subconsultas por sí sola no determina que una CTE sea mejor.

  • ¿Qué función cumple cada subconsulta?
  • ¿Alguna lógica se repite?
  • ¿Existen etapas claramente diferenciadas?
  • ¿La consulta actual resulta difícil de interpretar?
  • ¿El cambio mejora realmente la solución?

Una CTE puede facilitar una consulta compleja, pero utilizarla mecánicamente también puede generar estructuras innecesarias.

Situación 11

Una aplicación necesita acceder frecuentemente a un conjunto de datos construido mediante varias tablas. Los desarrolladores desean simplificar las consultas de la aplicación y evitar que cada consulta tenga que conocer toda la estructura interna de esas tablas.

¿Qué alternativa considerarías?
Pensá si la necesidad termina cuando finaliza una sentencia o debe seguir disponible.

Elección sugerida: vista

Además de reutilizar una consulta, una vista puede presentar una interfaz más simple sobre una estructura interna compleja.

CREATE VIEW datos_aplicacion AS SELECT ... FROM tabla1 JOIN tabla2 ... JOIN tabla3 ...;

Una CTE no resuelve del mismo modo esta necesidad porque su alcance queda limitado a la sentencia donde se declara.

Situación 12

Un desarrollador propone la siguiente regla:

“Si una consulta es corta, usar subconsulta. Si es larga, usar CTE. Si es muy larga, crear una vista.”
¿Considerás correcta esta regla?
Pensá qué criterios son realmente importantes para elegir entre los tres recursos.

Propuesta de análisis

No. La elección no depende simplemente de la cantidad de líneas.

  • dónde se necesita el resultado;
  • cuántas veces se utilizará;
  • si debe estar disponible solamente durante una sentencia;
  • si la lógica debe reutilizarse desde distintas consultas;
  • si existen etapas claramente diferenciadas;
  • qué alternativa hace más comprensible la intención de la solución.

Una consulta extensa podría resolverse correctamente con subconsultas y una consulta pequeña podría justificar una vista si esa lógica necesita reutilizarse.

CIERRE

Para pensar al terminar

  1. ¿Qué característica considerarías más importante para decidir entre una subconsulta y una CTE?
  2. ¿En qué momento dejarías de pensar solamente en cómo organizar una consulta y comenzarías a considerar la creación de una vista?
  3. ¿Puede una misma solución utilizar subconsultas, CTE y vistas al mismo tiempo? Explicalo con tus propias palabras.
  4. Frente a dos soluciones que producen exactamente el mismo resultado, ¿qué otros criterios utilizarías para decidir cuál conservar?
