Base de Datos I · MySQL

Trabajo Práctico Integrador

Consultas SQL sobre clientes, productos, pedidos y categorías.

Consigna general. Resolver las siguientes consultas utilizando las tablas de la base de datos provista. Aplicar, según corresponda, filtros, funciones, cálculos, JOIN, funciones de agregación, GROUP BY, HAVING y ordenamiento de resultados.

Diagrama Entidad-Relación

Ejercicio 1

Mostrar los productos activos con stock disponible cuyo precio esté entre $25.000 y $150.000. Mostrar nombre del producto, marca, categoría, precio y stock. Ordenar primero por categoría y luego de mayor a menor precio.

Ejercicio 2

Mostrar los pedidos realizados durante el primer semestre de 2026 cuyo estado sea Pagado o Pendiente. Mostrar id de pedido, fecha del pedido, nombre y apellido del cliente, estado y canal. Ordenar desde el pedido más reciente al más antiguo.

Ejercicio 3

Mostrar el detalle de los pedidos realizados por canal Web durante los meses de junio, julio y agosto de 2026. Mostrar id de pedido, fecha del pedido, nombre y apellido del cliente, nombre del producto, categoría, cantidad, precio del producto e importe correspondiente al producto. El importe debe calcularse multiplicando la cantidad por el precio del producto. Excluir los pedidos con estado Cancelado. Mostrar solamente los productos cuyo importe sea superior a $100.000.

Ejercicio 4

Considerando solamente pedidos Pagados realizados durante 2026, obtener en una única fila la cantidad de pedidos, la cantidad total de unidades vendidas, el importe total generado, el menor precio de producto vendido y el mayor precio de producto vendido.

Ejercicio 5

Mostrar para cada estado de pedido la cantidad de pedidos diferentes, la cantidad total de unidades incluidas y el importe total correspondiente. Considerar solamente pedidos realizados durante 2026. Ordenar de mayor a menor según el importe total.

Ejercicio 6

Mostrar para cada mes de 2026 el número de mes, la cantidad de pedidos pagados diferentes, la cantidad total de unidades vendidas y el importe total generado. Ordenar cronológicamente.

Ejercicio 7

Mostrar para cada cliente su nombre y apellido, la cantidad de pedidos pagados realizados durante 2026, la fecha del último pedido pagado y la cantidad de días transcurridos desde ese último pedido hasta la fecha actual. Mostrar solamente clientes que hayan realizado al menos 2 pedidos pagados. Ordenar de mayor a menor según la cantidad de días transcurridos.

Ejercicio 8

Mostrar para cada combinación de canal y estado la cantidad de pedidos diferentes, la cantidad total de unidades y el importe total generado. Considerar solamente los pedidos realizados en los últimos 3 meses. Mostrar únicamente las combinaciones que tengan al menos 2 pedidos diferentes.

Ejercicio 9

Mostrar para cada categoría el nombre de la categoría, la cantidad total de unidades vendidas y el importe total generado. Considerar solamente productos incluidos en pedidos Pagados realizados durante 2026. Mostrar únicamente las categorías que hayan vendido más de 10 unidades y cuyo importe total generado supere los $300.000. Ordenar de mayor a menor según el importe total.

Ejercicio 10

Mostrar todos los clientes, incluso aquellos que no hayan realizado ningún pedido. Mostrar id de cliente, nombre, apellido, cantidad de pedidos realizados, cantidad total de unidades compradas, fecha del primer pedido y fecha del último pedido. Para los clientes que no tengan unidades compradas, mostrar 0 en lugar de NULL. Ordenar de mayor a menor según la cantidad de pedidos.

Ejercicio 11 Integrador

Mostrar para cada combinación de mes de pedido y categoría el número de mes, nombre de la categoría, cantidad de pedidos diferentes en los que aparecieron productos de esa categoría, cantidad total de unidades vendidas e importe total generado. Considerar solamente pedidos Pagados realizados durante 2026 y productos activos. Mostrar únicamente los grupos que hayan vendido más de 10 unidades y generado más de $250.000. Ordenar primero por mes y, dentro de cada mes, de mayor a menor importe generado.

Script de la base de datos

El siguiente script se incluye para quienes quieran cargar la base en MySQL Workbench y corroborar los resultados de las consultas. Se recomienda resolver primero los ejercicios en papel y utilizar Workbench luego como instancia de verificación. 

CREATE DATABASE bdd1_tp_repaso_consultas
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

USE bdd1_tp_repaso_consultas;

-- =========================================================
-- TABLA: CLIENTES
-- =========================================================

CREATE TABLE clientes (
    cliente_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nombre_cliente VARCHAR(50) NOT NULL,
    apellido_cliente VARCHAR(50) NOT NULL,
    ciudad VARCHAR(60) NOT NULL,
    fecha_alta DATE NOT NULL,
    activo_cliente BOOLEAN NOT NULL DEFAULT TRUE
);

-- =========================================================
-- TABLA: CATEGORIAS
-- =========================================================

CREATE TABLE categorias (
    categoria_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nombre_categoria VARCHAR(60) NOT NULL UNIQUE
);

-- =========================================================
-- TABLA: PRODUCTOS
-- =========================================================

CREATE TABLE productos (
    producto_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    nombre_producto VARCHAR(80) NOT NULL,
    categoria_id INT UNSIGNED NOT NULL,
    marca VARCHAR(50) NOT NULL,
    precio DECIMAL(10,2) NOT NULL,
    stock INT UNSIGNED NOT NULL,
    activo_producto BOOLEAN NOT NULL DEFAULT TRUE,

    CONSTRAINT fk_productos_categorias
        FOREIGN KEY (categoria_id)
        REFERENCES categorias (categoria_id)
        ON UPDATE CASCADE
        ON DELETE RESTRICT
);

-- =========================================================
-- TABLA: PEDIDOS
-- =========================================================

CREATE TABLE pedidos (
    pedido_id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    cliente_id INT UNSIGNED NOT NULL,
    fecha_pedido DATE NOT NULL,
    estado ENUM('Pagado', 'Pendiente', 'Cancelado') NOT NULL,
    canal ENUM('Web', 'Local') NOT NULL,

    CONSTRAINT fk_pedidos_clientes
        FOREIGN KEY (cliente_id)
        REFERENCES clientes (cliente_id)
        ON UPDATE CASCADE
        ON DELETE RESTRICT
);

-- =========================================================
-- TABLA: DETALLES_PEDIDO
-- =========================================================

CREATE TABLE detalles_pedido (
    pedido_id INT UNSIGNED NOT NULL,
    producto_id INT UNSIGNED NOT NULL,
    cantidad INT UNSIGNED NOT NULL,

    PRIMARY KEY (pedido_id, producto_id),

    CONSTRAINT fk_detalles_pedidos
        FOREIGN KEY (pedido_id)
        REFERENCES pedidos (pedido_id)
        ON UPDATE CASCADE
        ON DELETE CASCADE,

    CONSTRAINT fk_detalles_productos
        FOREIGN KEY (producto_id)
        REFERENCES productos (producto_id)
        ON UPDATE CASCADE
        ON DELETE RESTRICT
);
