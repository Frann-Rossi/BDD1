01 · El problema original

Antes de las bases de datos

Las organizaciones siempre necesitaron registrar información. Lo que fue cambiando es la cantidad de datos, la velocidad de acceso requerida y el número de personas que necesitaban utilizarlos al mismo tiempo.

Registros manualesFichas, carpetas, libros, planillas impresas y archivos físicos.
Archivos digitales independientesCada programa guardaba sus propios archivos, con estructuras y reglas particulares.
Crecimiento de la informaciónMás usuarios, más operaciones y necesidad de relacionar datos de distintas áreas.
Sistemas de gestión de bases de datosUn software especializado centraliza reglas, accesos, consultas, seguridad y recuperación.

¿Qué problemas aparecían con archivos separados?

Duplicación

Mismo dato, varias copias

El domicilio de un alumno podía repetirse en múltiples archivos.

Inconsistencia

Copias que no coinciden

Una actualización podía hacerse en un archivo y olvidarse en otro.

Aislamiento

Información difícil de combinar

Cada aplicación podía utilizar un formato diferente.

Concurrencia

Varios usuarios a la vez

Dos personas podían intentar modificar el mismo dato simultáneamente.

Seguridad

Permisos poco precisos

Era difícil determinar quién podía consultar o modificar cada parte.

Recuperación

Fallos y pérdidas

Recuperar un estado consistente podía ser complejo o imposible.

Idea central: los archivos no desaparecieron. Las bases de datos también terminan almacenándose físicamente en archivos. La diferencia es que esos archivos son administrados por un sistema especializado, no directamente por cada usuario o programa.
02 · Vocabulario inicial

Datos, información y base de datos

Dato

Representación elemental de un hecho. Ejemplos: 1254, Ana, 2026-03-12.

Información

Datos interpretados dentro de un contexto. Ejemplo: “Ana está inscripta en Base de Datos I”.

Base de datos

Conjunto organizado de datos relacionados, diseñado para un propósito determinado y administrado mediante un SGBD.

Una primera imagen mental

Podemos imaginar una base académica llamada gestion_academica. Dentro de ella habrá objetos que representan alumnos, materias, docentes, comisiones e inscripciones.

gestion_academica
├── alumnos
├── materias
├── docentes
├── comisiones

Por ahora no necesitamos saber cómo se crean esas tablas. Primero debemos comprender quién las administra y cómo se conectan las distintas piezas.

03 · El administrador especializado

¿Qué es un SGBD?

Un Sistema de Gestión de Bases de Datos —SGBD o DBMS— es el software que permite crear, organizar, consultar, modificar, proteger y recuperar bases de datos.

Lo que recibe

Solicitudes de usuarios, aplicaciones y herramientas cliente. Muchas de esas solicitudes están escritas en SQL.

Lo que hace

Valida permisos, interpreta instrucciones, controla reglas, accede a los datos y devuelve resultados.

En esta materia: nuestro SGBD principal será MySQL Server. “MySQL” suele utilizarse como nombre general del producto, pero el componente que permanece ejecutándose y atiende conexiones es el servidor.

04 · Lenguaje y dialectos

SQL no es lo mismo que MySQL

SQL es un lenguaje utilizado para definir estructuras, manipular datos y realizar consultas. Distintos gestores implementan ese lenguaje y agregan características propias.

MySQL

Gestor desarrollado actualmente por Oracle. Utiliza SQL y agrega su sintaxis y funcionalidades.

SQL Server

Gestor de Microsoft. Su dialecto se denomina Transact-SQL o T-SQL.

Otros gestores

PostgreSQL, Oracle Database, MariaDB, SQLite y muchos más.

Mismo objetivo, distinta sintaxis

Para generar automáticamente un identificador, MySQL y SQL Server utilizan palabras diferentes:

MySQL

id_alumno INT AUTO_INCREMENT PRIMARY KEY

SQL Server

id_alumno INT IDENTITY(1, 1) PRIMARY KEY
Regla práctica: antes de copiar una consulta de Internet, verificar para qué gestor fue escrita. En esta materia, toda la práctica obligatoria utilizará sintaxis compatible con MySQL.
05 · Cada pieza en su lugar

El ecosistema MySQL

Estas palabras suelen mezclarse al comenzar. El siguiente esquema las separa:

Interfaz clienteWorkbench, DBeaver, HeidiSQL, aplicación propia o consola.
↓ solicitud SQL · ↑ resultados
MySQL ServerPrograma que recibe conexiones, interpreta SQL, controla usuarios y coordina las operaciones.
↓ operaciones de almacenamiento
Motor InnoDBComponente que organiza tablas e índices y aporta transacciones, concurrencia y recuperación.
↓ lectura y escritura
Directorio de datosArchivos y estructuras internas almacenadas en el disco y administradas por el servidor.

La respuesta corta a una pregunta frecuente

¿MySQL es el servidor o necesita otro servidor para funcionar?
MySQL Server es, justamente, el software servidor de bases de datos. No necesita “otro servidor de base de datos” por debajo. Sí necesita un sistema operativo y una computadora —física o virtual— donde ejecutarse.

Dos usos de la palabra “servidor”

Servidor como software

El proceso de MySQL Server, normalmente denominado mysqld, que atiende conexiones y administra datos.

Servidor como equipo

La computadora donde se ejecuta ese software. Puede ser tu propia PC, otra máquina de la red o un equipo en Internet.

06 · Arquitectura cliente-servidor

¿Por qué Workbench necesita un servidor?

Workbench es una aplicación cliente: permite escribir instrucciones y visualizar resultados, pero no administra por sí mismo los archivos de la base de datos.

Cliente

Ejemplo: MySQL Workbench

El usuario escribe una consulta y configura a qué servidor desea conectarse.

⇄red o conexión local

Servidor

Ejemplo: MySQL Server

Recibe la consulta, la ejecuta, accede a los datos y devuelve el resultado.

SELECT *
FROM alumnos;
  1. El alumno escribe la consulta en Workbench.
  2. Workbench la envía a MySQL Server.
  3. El servidor verifica sintaxis, permisos y objetos involucrados.
  4. El motor accede a los datos correspondientes.
  5. MySQL Server devuelve las filas.
  6. Workbench las presenta en una grilla.
¿Puedo tener Workbench sin MySQL Server?
Sí. Workbench puede conectarse con un MySQL Server instalado en otra computadora. Si no existe ningún servidor local o remoto disponible, la interfaz abrirá, pero no habrá una base sobre la cual ejecutar consultas.
¿Puedo tener MySQL Server sin Workbench?
Sí. El servidor puede administrarse con la consola, una aplicación propia u otro cliente gráfico. Workbench es útil, pero no es obligatorio.
¿Qué significa localhost?
Indica que el cliente intenta conectarse con un servidor que se ejecuta en la misma computadora. En una instalación habitual, MySQL escucha conexiones en el puerto 3306, aunque este valor puede configurarse.
07 · Una confusión muy habitual

¿MySQL necesita XAMPP?

No. MySQL Server puede instalarse y ejecutarse sin XAMPP. En Windows, una instalación de los productos de MySQL puede incluir el servidor y Workbench dentro del mismo proceso de instalación, pero siguen siendo programas diferentes.

Instalación directa de MySQL

Se instala MySQL Server y, si se desea, MySQL Workbench. El servicio del servidor puede iniciarse automáticamente con Windows.

Entorno XAMPP

Es un paquete orientado al desarrollo web que reúne Apache, MariaDB, PHP, Perl y otras herramientas bajo un panel de control.

Dato importante: las versiones actuales de XAMPP incluyen MariaDB, no MySQL Server, aunque en algunos botones, carpetas o explicaciones todavía pueda aparecer la palabra “MySQL”. MariaDB comparte gran parte del origen y la sintaxis básica, pero es otro producto.

Entonces, ¿para qué se usa XAMPP?

Se utiliza con frecuencia para preparar rápidamente un entorno local de desarrollo web. Desde su panel se pueden iniciar varios servicios:

ComponenteFunción¿Es necesario para practicar SQL en MySQL?
ApacheServidor web para publicar páginas y aplicaciones.No.
MariaDBServidor de bases de datos incluido actualmente por XAMPP.No, si ya se utiliza MySQL Server.
PHPLenguaje utilizado frecuentemente en aplicaciones web.No.
phpMyAdminInterfaz web para administrar MySQL/MariaDB.No.
Elección de la materia: trabajaremos con MySQL Server + MySQL Workbench. XAMPP puede aparecer en otras materias, tutoriales o máquinas, pero no es un requisito de MySQL ni reemplaza la explicación de qué componente cumple cada función.
08 · Del concepto al disco

¿Dónde está físicamente la base de datos?

Una base de datos es un conjunto lógico de objetos, pero el servidor debe guardar su información en archivos y estructuras del disco. MySQL denomina directorio de datos al lugar principal donde conserva la información administrada.

En una instalación típica de Windows, una ruta posible es:

C:\ProgramData\MySQL\MySQL Server 8.0\Data\

En instalaciones de MySQL 8.4 podría aparecer una carpeta equivalente con el número de versión correspondiente. La ubicación puede modificarse, por lo que no conviene memorizar una ruta como si fuera universal.

Consultar la ubicación real

SHOW VARIABLES LIKE 'datadir';
No abrir, mover ni borrar manualmente esos archivos. Las bases deben administrarse mediante SQL y herramientas de exportación, backup y restauración. Manipular el directorio de datos por fuera del servidor puede producir inconsistencias o pérdida de información.
¿Cada tabla es siempre un único archivo?
No necesariamente. La organización física depende del motor, la configuración y el tipo de tablespace. Para comenzar, alcanza con comprender que MySQL Server administra esas estructuras y que nosotros trabajamos con objetos lógicos mediante SQL.
09 · Distintas puertas de entrada

Workbench y otras interfaces

El mismo servidor puede recibir conexiones desde varias herramientas. Cambia la interfaz, pero la base de datos continúa bajo control de MySQL Server.

Workbench

Cliente gráfico oficial para MySQL. Incluye editor SQL, administración y modelado.

DBeaver

Cliente multiplataforma capaz de conectarse con numerosos gestores.

HeidiSQL

Cliente gráfico liviano compatible con MySQL, MariaDB y otros sistemas.

Consola

Permite conectarse y ejecutar SQL sin una interfaz gráfica.

mysql -u root -p
Prueba mental: si se desinstala Workbench pero MySQL Server y sus datos permanecen, la base no desaparece. Todavía se puede acceder desde otra interfaz.
10 · Distintas formas de organizar datos

Modelos de bases de datos

Un modelo establece cómo se representan y relacionan los datos. Existen distintos enfoques; esta materia se concentrará en el modelo relacional.

JerárquicoOrganiza datos con una estructura similar a un árbol.
En redPermite conexiones más flexibles entre registros.
RelacionalOrganiza información en tablas vinculadas mediante claves. Es el eje de la cursada.
DocumentalAlmacena documentos con estructuras flexibles, por ejemplo JSON.

En el modelo relacional trabajaremos con tablas, filas, columnas, dominios, claves y restricciones. Más adelante diseñaremos primero un modelo conceptual y luego lo transformaremos en tablas de MySQL.

Panorama, no sobrecarga: conocer que existen otros modelos evita pensar que todas las bases de datos funcionan de la misma manera. Sin embargo, los ejercicios obligatorios de esta materia se desarrollarán sobre el modelo relacional.

13 · Detenerse y comprobar

Preguntas de comprensión

Intentá responder antes de desplegar cada solución.

1. ¿Workbench es la base de datos?
No. Workbench es una interfaz cliente. La base es el conjunto organizado de objetos y datos administrados por MySQL Server.
2. ¿Necesito Apache para ejecutar consultas SQL en MySQL?
No. Apache es un servidor web. MySQL Server puede funcionar sin Apache.
3. ¿XAMPP es obligatorio para usar MySQL?
No. MySQL Server puede instalarse directamente. Además, las versiones actuales de XAMPP incluyen MariaDB como servidor de bases de datos.
4. Si MySQL Server está detenido, ¿Workbench puede ejecutar consultas?
No sobre ese servidor. Workbench necesita conectarse con una instancia en funcionamiento, ya sea local o remota.
5. ¿SQL y MySQL significan lo mismo?
No. SQL es el lenguaje. MySQL es un sistema gestor que implementa SQL y agrega características propias.
6. ¿Qué componente suele encargarse del almacenamiento de las tablas en MySQL?
El motor de almacenamiento. En MySQL 8, InnoDB es el motor predeterminado habitual.

Actividad breve · Inspeccionar tu instalación

  1. Abrir MySQL Workbench y observar el nombre de la conexión.
  2. Identificar el host. Si indica localhost o 127.0.0.1, el servidor está en la misma máquina.
  3. Observar el puerto configurado.
  4. Ejecutar SHOW VARIABLES LIKE 'datadir';.
  5. Escribir con tus palabras qué elemento es la interfaz, cuál es el servidor y cuál es la base.
14 · Cierre

Síntesis de la unidad

  • Las bases de datos surgieron para resolver problemas de duplicación, inconsistencia, aislamiento, seguridad y acceso concurrente.
  • La base de datos contiene los objetos y datos de un dominio; el SGBD los administra.
  • SQL es un lenguaje. MySQL, SQL Server y otros productos implementan dialectos de ese lenguaje.
  • MySQL Server es el software servidor. Workbench es una interfaz cliente.
  • InnoDB es el motor de almacenamiento predeterminado habitual en MySQL 8.
  • XAMPP no es necesario para MySQL y actualmente incluye MariaDB.
  • Los datos se almacenan físicamente en un directorio administrado por el servidor y no deben manipularse manualmente.
  • La materia se centrará en el modelo relacional y utilizará una base académica como hilo conductor.
