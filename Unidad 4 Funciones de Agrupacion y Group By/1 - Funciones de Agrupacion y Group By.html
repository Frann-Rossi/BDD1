01 · Cambiar la pregunta

De filas individuales a información resumida

Una consulta común devuelve filas. Una consulta agregada permite calcular un resultado a partir de muchas filas.

Pregunta sobre filas

“Mostrar los pedidos pagados”.

SELECT id_pedido, fecha, total
FROM pedidos
WHERE estado = 'Pagado';

Pregunta sobre el conjunto

“¿Cuánto suman todos los pedidos pagados?”.

SELECT SUM(total) AS total_pagado
FROM pedidos
WHERE estado = 'Pagado';
Idea central: las funciones de agregación toman muchas filas y producen un valor resumen. Con GROUP BY, ese resumen puede calcularse una vez por cada grupo.
02 · Cinco funciones fundamentales

COUNT, SUM, AVG, MIN y MAX

COUNT()

Contar filas o valores no nulos.

SUM()

Sumar valores numéricos.

AVG()

Calcular un promedio.

MIN()

Obtener el menor valor.

MAX()

Obtener el mayor valor.

SELECT
    COUNT(*) AS cantidad_pedidos,
    SUM(total) AS facturacion,
    AVG(total) AS ticket_promedio,
    MIN(total) AS pedido_menor,
    MAX(total) AS pedido_mayor
FROM pedidos;

Sin GROUP BY, toda la tabla —o todas las filas que superaron un WHERE— se considera un único conjunto para el cálculo.

¿Qué diferencia hay entre COUNT(*) y COUNT(columna)?
COUNT(*) cuenta filas. COUNT(columna) cuenta solamente las filas donde esa columna no es NULL. Esta diferencia es importante y se retoma en el siguiente apartado.
¿Y COUNT(DISTINCT columna)?
Cuenta cuántos valores diferentes y no nulos aparecen en la columna. Por ejemplo, COUNT(DISTINCT id_cliente) permite conocer cuántos clientes diferentes realizaron pedidos.
03 · NULL cambia el cálculo

Qué hacen las funciones de agregación con NULL

Las funciones no tratan a NULL como cero ni como cadena vacía. En general, SUM, AVG, MIN y MAX ignoran los valores NULL. COUNT permite ver muy bien la diferencia.

idobservaciones
1Entrega por la tarde
2NULL
3'' cadena vacía
4NULL
SELECT
    COUNT(*) AS filas,
    COUNT(observaciones) AS observaciones_no_nulas
FROM pedidos;

COUNT(*)

Cuenta las 4 filas.

COUNT(observaciones)

Cuenta 2 valores: el texto y la cadena vacía. Los dos NULL no se cuentan.

Conexión con la Unidad 2: una cadena vacía sigue siendo un valor y por eso COUNT(columna) la cuenta. NULL representa ausencia de valor y no se cuenta.
Atención con AVG: si algunos valores son NULL, el promedio se calcula sobre los valores conocidos, no dividiendo por la cantidad total de filas.
04 · Un resumen por cada grupo

GROUP BY

GROUP BY reúne las filas que comparten uno o más valores y permite calcular agregaciones para cada grupo.

SELECT
    estado,
    COUNT(*) AS cantidad,
    SUM(total) AS importe
FROM pedidos
GROUP BY estado;

Si existen pedidos con estado Pagado, Pendiente y Cancelado, el resultado tendrá una fila por cada estado, no una fila por cada pedido.

Regla de trabajo de la cátedra: si una columna aparece en SELECT y no está dentro de una función de agregación, incluirla explícitamente en GROUP BY. Evita resultados ambiguos y genera consultas claras.
05 · Grupos más específicos

Agrupar por más de una columna

Cada combinación diferente de valores forma un grupo.

SELECT
    canal,
    estado,
    COUNT(*) AS cantidad,
    SUM(total) AS importe
FROM pedidos
GROUP BY canal, estado
ORDER BY canal, estado;

¿Qué cambia al agregar una segunda columna al GROUP BY? Si agrupáramos solamente por estado, todos los pedidos con estado Pagado quedarían dentro de un mismo grupo, sin importar por qué canal se realizaron.

En cambio, al escribir GROUP BY canal, estado, MySQL forma un grupo diferente por cada combinación de valores que realmente exista en los datos. Por ejemplo, Web + Pagado es un grupo distinto de Local + Pagado, aunque ambos compartan el mismo estado.

Idea clave: agrupar por dos columnas significa agrupar por la combinación de ambas. No se crean combinaciones inventadas: solo aparecen aquellas que existen en las filas consultadas.
06 · Dos filtros, dos momentos distintos

WHERE filtra filas · HAVING filtra grupos

WHERE

Actúa sobre filas individuales antes de agrupar.

WHERE estado = 'Pagado'

HAVING

Actúa sobre los grupos después de calcular las agregaciones.

HAVING SUM(total) > 100000
SELECT
    id_cliente,
    COUNT(*) AS pedidos_pagados,
    SUM(total) AS total_pagado
FROM pedidos
WHERE estado = 'Pagado'
GROUP BY id_cliente
HAVING SUM(total) > 100000;

Primero se descartan los pedidos que no están pagados. Después se agrupan los restantes por cliente. Por último, HAVING conserva solamente los grupos cuya suma supera 100000.

Error típico: escribir WHERE COUNT(*) > 2. En el momento lógico en que se evalúa WHERE, los grupos todavía no fueron creados.
07 · Una consulta no se entiende sólo de arriba hacia abajo

Orden de escritura vs. orden lógico de procesamiento

SQL se escribe comenzando por SELECT, pero conceptualmente el motor necesita resolver antes de dónde salen las filas, cuáles sobreviven al filtro y cómo se forman los grupos.

Orden de escritura

  1. SELECT
  2. FROM / JOIN
  3. WHERE
  4. GROUP BY
  5. HAVING
  6. ORDER BY
  7. LIMIT / OFFSET

Orden lógico aproximado

  1. FROM / JOIN
  2. WHERE
  3. GROUP BY
  4. HAVING
  5. SELECT
  6. ORDER BY
  7. LIMIT / OFFSET
Esto es un orden lógico, no un mapa exacto de ejecución física. El optimizador de MySQL puede elegir distintas estrategias internas para ejecutar una consulta. La secuencia sirve para comprender qué información existe en cada etapa.

Un caso clásico: crear un alias en SELECT y querer usarlo antes

Los alias de columna se definen en la lista del SELECT. Esto genera una situación muy común: crear un nombre cómodo para un cálculo y después intentar utilizar ese nombre en otra cláusula.

No funciona en WHERE

SELECT
    estado,
    SUM(total) AS total_estado
FROM pedidos
WHERE total_estado > 100000
GROUP BY estado;

WHERE no puede utilizar el alias total_estado. En el orden lógico, el filtro de filas ocurre antes de que se construyan las columnas del SELECT.

Una forma segura

SELECT
    estado,
    SUM(total) AS total_estado
FROM pedidos
GROUP BY estado
HAVING SUM(total) > 100000
ORDER BY total_estado DESC;

La expresión agregada se repite en HAVING. El alias se conserva para presentar y ordenar el resultado.

En MySQL 8: un alias definido en SELECT puede utilizarse en GROUP BY, HAVING y ORDER BY, pero no en WHERE.

Por ejemplo, MySQL 8 también acepta:

SELECT
    estado,
    SUM(total) AS total_estado
FROM pedidos
GROUP BY estado
HAVING total_estado > 100000
ORDER BY total_estado DESC;
Criterio práctico de la cátedra: las reglas relacionadas con alias han tenido diferencias entre versiones, configuraciones y gestores. Ante la duda, conviene no depender de alias en GROUP BY o HAVING y repetir la columna o expresión correspondiente. Esto hace la consulta más previsible y portable. En WHERE el alias del SELECT no debe utilizarse. En ORDER BY su uso es habitual y claro.

Importante: que MySQL 8 permita un alias en GROUP BY o HAVING no cambia el orden lógico mostrado arriba. Se trata de una regla del gestor para resolver nombres, no de que SELECT pase a ejecutarse antes.

Por qué una agregación no va directamente en WHERE

Incorrecto

SELECT estado, COUNT(*)
FROM pedidos
WHERE COUNT(*) > 2
GROUP BY estado;

Correcto

SELECT estado, COUNT(*)
FROM pedidos
GROUP BY estado
HAVING COUNT(*) > 2;
08 · Integrar la Unidad 3

JOIN y funciones de agregación

Como ya conocemos JOINs, podemos agrupar información que proviene de tablas relacionadas.

SELECT
    c.id_cliente,
    c.nombre,
    COUNT(p.id_pedido) AS cantidad_pedidos,
    SUM(p.total) AS total_comprado
FROM clientes AS c
INNER JOIN pedidos AS p
    ON p.id_cliente = c.id_cliente
GROUP BY c.id_cliente, c.nombre
ORDER BY total_comprado DESC;

La relación se resuelve primero con el JOIN. Luego las filas resultantes se agrupan por cliente y se calculan las funciones.

¿Cómo conservar también clientes que todavía no tienen pedidos?
Utilizar LEFT JOIN desde clientes. En ese caso es especialmente útil COUNT(p.id_pedido): para un cliente sin coincidencias devuelve 0, mientras que COUNT(*) contaría la fila externa generada por el LEFT JOIN.
09 · Revisar antes de ejecutar

Errores frecuentes

  • Confundir COUNT(*) con COUNT(columna).
  • Suponer que NULL equivale a cero o a una cadena vacía.
  • Seleccionar columnas descriptivas sin incluirlas en GROUP BY.
  • Usar WHERE para filtrar un resultado agregado.
  • Usar HAVING para condiciones que podrían filtrar filas antes de agrupar.
  • Agrupar por demasiadas columnas y terminar creando grupos excesivamente pequeños.
  • Olvidar que un JOIN puede multiplicar filas y, por lo tanto, alterar una suma o un conteo si la relación no se comprende correctamente.
10 · Leer una consulta completa

Consulta integradora

SELECT
    c.ciudad,
    COUNT(*) AS cantidad_pedidos,
    SUM(p.total) AS facturacion,
    AVG(p.total) AS ticket_promedio
FROM clientes AS c
INNER JOIN pedidos AS p
    ON p.id_cliente = c.id_cliente
WHERE p.estado = 'Pagado'
GROUP BY c.ciudad
HAVING SUM(p.total) > 150000
ORDER BY facturacion DESC
LIMIT 5;
Leerla lógicamente: relacionar clientes y pedidos → conservar sólo pagados → agrupar por ciudad → calcular y filtrar los grupos → construir las columnas del resultado → ordenar → limitar.
11 · Síntesis

Con qué idea quedarse

Las funciones de agregación responden preguntas sobre conjuntos. GROUP BY divide ese conjunto en grupos, WHERE decide qué filas llegan al agrupamiento y HAVING decide qué grupos sobreviven después del cálculo.

Secuencia mental: ¿de dónde salen las filas? → ¿cuáles necesito? → ¿cómo las agrupo? → ¿qué cálculo hago? → ¿qué grupos quiero conservar?
