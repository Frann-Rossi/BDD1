Unidad 5 · Subconsultas · MySQL 8

Resolver una consulta apoyándonos en el resultado de otra

Una subconsulta aparece cuando para responder una pregunta necesitamos resolver primero otra más pequeña. El objetivo de esta unidad no es memorizar paréntesis: es aprender a reconocer qué devuelve la consulta interna y cómo usar ese resultado correctamente.

EscalaresListasMatricialesCorrelacionadasEXISTS / NOT EXISTS

Al terminar esta unidad

  • Reconocer una consulta externa y una subconsulta.
  • Clasificar subconsultas por la forma de su resultado: escalar, lista y matricial.
  • Distinguir subconsultas independientes de subconsultas correlacionadas.
  • Elegir entre =, IN, ANY/SOME, ALL, EXISTS y NOT EXISTS.
  • Utilizar subconsultas en SELECT, WHERE, FROM y HAVING.
  • Comparar conceptualmente una solución con subconsulta frente a alternativas con JOIN o GROUP BY.

01 · Punto de partida

Qué es una subconsulta

Una subconsulta es una consulta SELECT escrita dentro de otra instrucción SQL. También puede encontrarse con los nombres consulta anidada o subquery.

SELECT columnas
FROM tabla
WHERE columna operador (
    SELECT columna_o_calculo
    FROM otra_tabla
    WHERE condicion
);

Consulta externa

Es la consulta principal. Produce el resultado que finalmente vemos.

Consulta interna

Es la subconsulta. Produce el valor, conjunto o tabla que la consulta externa necesita utilizar.

Idea central: si para contestar una pregunta necesito responder primero otra pregunta, probablemente exista una oportunidad clara para utilizar una subconsulta.

Primer ejemplo: productos más caros que el promedio

Primero necesitamos conocer el promedio:

SELECT AVG(precio)
FROM productos;

Después utilizamos ese resultado directamente, sin copiarlo a mano:

SELECT nombre, precio
FROM productos
WHERE precio > (
    SELECT AVG(precio)
    FROM productos
);

Lectura: mostrar los productos cuyo precio sea mayor que el promedio de todos los productos.

02 · Un contexto común para todos los ejemplos

Base de datos de trabajo

Para no cambiar de escenario en cada ejemplo utilizaremos una tienda sencilla con clientes, productos, ventas y detalle de ventas.

clientes

id_cliente, nombre, ciudad, edad.

productos

id_producto, nombre, categoria, precio.

ventas

id_venta, id_cliente, fecha.

detalle_ventas

id_detalle, id_venta, id_producto, cantidad, precio_unitario.

Script completo para crear y cargar la base de ejemplo 
DROP DATABASE IF EXISTS tienda_subconsultas;

    id_cliente INT PRIMARY KEY,
    nombre VARCHAR(80) NOT NULL,

);

CREATE TABLE productos (

    nombre VARCHAR(80) NOT NULL,

);

CREATE TABLE ventas (
    id_venta INT PRIMARY KEY,
    id_cliente INT NOT NULL,
    fecha DATE NOT NULL,

    FOREIGN KEY (id_venta) REFERENCES ventas(id_venta),

03 · Antes de escribir SQL

Cómo clasificar una subconsulta

Hay dos preguntas diferentes que conviene separar. La primera es qué forma tiene el resultado. La segunda es si la consulta interna depende o no de la consulta externa.

A. Según la forma del resultado

TipoQué devuelveImagen mentalUso habitual
EscalarUna fila y una columna.Un solo valor.=, >, <, expresiones, SELECT.
ListaVarias filas y una columna.Una columna de valores.IN, NOT IN, ANY, SOME, ALL.
Matricial o tabularVarias filas y/o varias columnas.Una pequeña tabla.Principalmente como tabla derivada en FROM.
ExistenciaNo interesan los valores: importa si aparece al menos una fila.Verdadero / falso.EXISTS, NOT EXISTS.
Sobre el término “matricial”: lo conservamos porque aparece en material clásico de la materia. En SQL actual, cuando ese resultado tabular se coloca dentro de FROM, suele hablarse de tabla derivada. Algunos textos separan además la “subconsulta de fila” —una fila con varias columnas—; aquí la incluimos dentro de la idea tabular para no multiplicar etiquetas.

B. Según la dependencia respecto de la consulta externa

Independiente o no correlacionada

Puede ejecutarse sola porque no necesita ninguna columna de la consulta exterior.

SELECT AVG(precio)
FROM productos;

Correlacionada o relacionada

Utiliza una columna de la consulta externa. Por eso necesita saber qué fila exterior se está evaluando.

SELECT AVG(p2.precio)
FROM productos AS p2
WHERE p2.categoria = p1.categoria;
No son categorías excluyentes: “escalar, lista o matricial” describe la forma del resultado. “Correlacionada” describe la dependencia con la consulta externa. Una subconsulta correlacionada puede ser, por ejemplo, escalar.
04 · Un único valor

Subconsultas escalares

Una subconsulta escalar devuelve exactamente una fila y una columna. Por eso su resultado puede utilizarse como si fuera un número, una fecha o un texto.

Producto o productos con el precio máximo

SELECT id_producto, nombre, precio
FROM productos
WHERE precio = (
    SELECT MAX(precio)
    FROM productos
);

La subconsulta devuelve un solo valor: el máximo precio. La consulta externa puede devolver varias filas si existen productos empatados en ese precio.

Subconsulta escalar dentro del SELECT

SELECT
    nombre,
    precio,
    (SELECT AVG(precio) FROM productos) AS promedio_general
FROM productos;
Cuidado con la cardinalidad: si una subconsulta utilizada como valor devuelve más de una fila, MySQL no puede decidir cuál utilizar y producirá un error. Antes de integrarla, conviene ejecutarla sola y verificar qué devuelve.
05 · Una columna, varias filas

Subconsultas de lista · IN y NOT IN

Una subconsulta de lista devuelve una columna con cero, una o muchas filas. La consulta externa compara un dato contra ese conjunto.

Clientes que realizaron al menos una compra

SELECT id_cliente, nombre
FROM clientes
WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
);

Lectura: mostrar clientes cuyo identificador aparezca dentro de la lista de identificadores registrados en ventas.

Productos que nunca fueron vendidos

SELECT id_producto, nombre
FROM productos
WHERE id_producto NOT IN (
    SELECT id_producto
    FROM detalle_ventas
);
NOT IN y NULL: si la subconsulta puede devolver NULL, el resultado puede resultar inesperado. Cuando la pregunta es “¿qué registros no tienen relación?”, suele ser más seguro y expresivo pensar en NOT EXISTS.

Un valor

Si la subconsulta devuelve un solo valor, puede tener sentido utilizar =, >, <, etc.

Una lista

Si puede devolver varias filas, no debemos tratarla como un único valor. Para pertenencia utilizamos IN.

06 · Comparar contra varios valores

ANY, SOME y ALL

ANY, SOME y ALL permiten combinar operadores de comparación —por ejemplo > o <— con una subconsulta que devuelve una lista.

ANY / SOME

La condición alcanza con que sea verdadera frente a alguno de los valores. En SQL, SOME es sinónimo de ANY.

SELECT nombre, precio
FROM productos
WHERE precio > ANY (
    SELECT precio
    FROM productos
    WHERE categoria = 'Libreria'
);

Lectura: precio mayor que al menos uno de los precios de Librería.

ALL

La condición debe ser verdadera frente a todos los valores devueltos por la subconsulta.

SELECT nombre, precio
FROM productos
WHERE precio > ALL (
    SELECT precio
    FROM productos
    WHERE categoria = 'Libreria'
);

Lectura: precio mayor que todos los precios de Librería.

CondiciónIdea rápida
> ANY (lista)Mayor que al menos un valor; intuitivamente, alcanza con superar al menor.
> ALL (lista)Mayor que todos; debe superar al mayor.
< ANY (lista)Menor que al menos uno; alcanza con estar por debajo del mayor.
< ALL (lista)Menor que todos; debe estar por debajo del menor.
No memorizar por reflejo: traducir primero la pregunta al castellano —“alguno” o “todos”— y recién después elegir ANY/SOME o ALL.
07 · Un resultado con forma de tabla

Subconsultas matriciales y tablas derivadas

Cuando la subconsulta produce varias filas y varias columnas, su resultado se parece a una tabla. Una de las formas más claras de utilizarlo es dentro de FROM.

Primero construir un resumen por cliente

SELECT
    v.id_cliente,
    SUM(dv.cantidad * dv.precio_unitario) AS total_gastado
FROM ventas AS v
INNER JOIN detalle_ventas AS dv
    ON dv.id_venta = v.id_venta
GROUP BY v.id_cliente;

Ese resultado tiene dos columnas y varias filas. Podemos usarlo como una tabla derivada:

SELECT
    resumen.id_cliente,
    resumen.total_gastado
FROM (
    SELECT
        v.id_cliente,
        SUM(dv.cantidad * dv.precio_unitario) AS total_gastado
    FROM ventas AS v
    INNER JOIN detalle_ventas AS dv
        ON dv.id_venta = v.id_venta
    GROUP BY v.id_cliente
) AS resumen
WHERE resumen.total_gastado > 50000;
Alias obligatorio: una subconsulta ubicada en FROM debe tener un nombre para que la consulta exterior pueda referirse a ella. En el ejemplo, ese nombre es resumen.

La tabla derivada existe únicamente durante la ejecución de esa instrucción. No queda guardada como una tabla real ni como una vista.

08 · Preguntar si hay filas relacionadas

EXISTS y NOT EXISTS

EXISTS no pregunta “¿qué valor devuelve?”. Pregunta simplemente: ¿la subconsulta devuelve al menos una fila?

Clientes que compraron

SELECT c.id_cliente, c.nombre
FROM clientes AS c
WHERE EXISTS (
    SELECT 1
    FROM ventas AS v
    WHERE v.id_cliente = c.id_cliente
);

Para cada cliente se verifica si existe al menos una venta asociada.

Clientes que nunca compraron

SELECT c.id_cliente, c.nombre
FROM clientes AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM ventas AS v
    WHERE v.id_cliente = c.id_cliente
);

EXISTS

Verdadero si la subconsulta devuelve al menos una fila.

NOT EXISTS

Verdadero si la subconsulta no devuelve ninguna fila.

¿Por qué aparece SELECT 1?
Con EXISTS no interesa el contenido de las columnas seleccionadas. Solo importa si existe una fila. Por eso es habitual escribir SELECT 1: deja explícita esa intención.
Pregunta guía: cuando el enunciado dice “clientes que tengan…”, “productos que hayan…”, “alumnos que no posean…” o “registros para los que exista/no exista…”, conviene pensar inmediatamente en EXISTS o NOT EXISTS.
09 · La consulta interna necesita a la externa

Subconsultas correlacionadas

Una subconsulta correlacionada —también llamada relacionada en materiales anteriores— utiliza una columna perteneciente a la consulta externa. Por eso no puede interpretarse completamente sin conocer la fila exterior que se está evaluando.

Producto más caro que el promedio de su propia categoría

SELECT
    p1.id_producto,
    p1.nombre,
    p1.categoria,
    p1.precio
FROM productos AS p1
WHERE p1.precio > (
    SELECT AVG(p2.precio)
    FROM productos AS p2
    WHERE p2.categoria = p1.categoria
);

La expresión p1.categoria pertenece a la consulta externa. La subconsulta necesita ese dato para calcular el promedio correspondiente a la categoría del producto actual.

Dicho simple: para entender la lógica podemos imaginar que SQL toma un producto y pregunta “¿su precio supera el promedio de su categoría?”. Luego evalúa el siguiente. Esa es una forma mental de comprender la correlación, no una descripción obligatoria del plan físico que elegirá el optimizador.

Una correlacionada escalar en SELECT

SELECT
    c.id_cliente,
    c.nombre,
    (
        SELECT COUNT(*)
        FROM ventas AS v
        WHERE v.id_cliente = c.id_cliente
    ) AS cantidad_ventas
FROM clientes AS c;

Esta subconsulta es correlacionada por depender de c.id_cliente y es además escalar porque COUNT(*) devuelve un único valor.

Rendimiento: una correlacionada puede expresar el problema con mucha claridad, pero en conjuntos grandes puede ser más costosa que otra formulación. Primero debemos entender la lógica; luego, cuando sea necesario, comparar alternativas y planes de ejecución.
10 · Dónde puede aparecer

Subconsultas en SELECT, WHERE, FROM y HAVING

CláusulaPara qué puede servirEjemplo mental
SELECTAgregar un cálculo como una columna del resultado.Cantidad de ventas de cada cliente.
WHEREFiltrar filas comparándolas con un valor, una lista o una condición de existencia.Productos por encima del promedio.
FROMUsar un resultado intermedio como si fuera una tabla.Resumen de gasto por cliente.
HAVINGFiltrar grupos comparándolos contra un cálculo obtenido por otra consulta.Grupos cuyo total supera un promedio calculado.

Ejemplo en HAVING

SELECT
    v.id_cliente,
    COUNT(*) AS cantidad_ventas
FROM ventas AS v
GROUP BY v.id_cliente
HAVING COUNT(*) > (
    SELECT AVG(cantidad)
    FROM (
        SELECT COUNT(*) AS cantidad
        FROM ventas
        GROUP BY id_cliente
    ) AS ventas_por_cliente
);

La tabla derivada calcula cuántas ventas tiene cada cliente. Luego se obtiene el promedio de esas cantidades y HAVING conserva los grupos que quedan por encima.

Este ejemplo es más avanzado: no hace falta memorizarlo. Lo importante es reconocer que una subconsulta puede aportar un valor intermedio también dentro de HAVING.
11 · Una idea que empieza a ser importante

Pensar en conjuntos, no en bucles

SQL es un lenguaje declarativo: describimos qué conjunto de datos queremos obtener. No escribimos un ciclo que recorra manualmente las filas.

Forma de pensar procedural

“Recorrer cada cliente, buscar sus ventas, contar, guardar el resultado y seguir con el próximo.”

Forma de pensar SQL

“Obtener los clientes para los que exista una venta” o “calcular la cantidad de ventas asociada a cada cliente”.

En una subconsulta correlacionada resulta útil imaginar conceptualmente una evaluación vinculada a cada fila externa. Sin embargo, eso no significa que MySQL esté obligado a ejecutar físicamente un bucle literal; el optimizador puede transformar la consulta y elegir otra estrategia.

Primer acercamiento al enfoque set-based: pensar en conjuntos y relaciones permite expresar el problema de forma declarativa. Esta idea se seguirá profundizando en consultas más avanzadas.
12 · Herramientas distintas para preguntas distintas

¿Subconsulta, JOIN o GROUP BY?

No todo problema que admite una subconsulta debe resolverse necesariamente con una. Una misma pregunta puede tener más de una formulación válida.

Necesidad principalHerramienta que suele expresar bien la idea
Comparar contra un promedio, máximo o mínimo.Subconsulta escalar.
Comprobar pertenencia a un conjunto.IN con subconsulta de lista.
Comprobar existencia o ausencia de filas relacionadas.EXISTS / NOT EXISTS.
Mostrar columnas provenientes de varias tablas relacionadas.JOIN.
Calcular resultados por grupo.GROUP BY.
Consultar un resultado intermedio con varias columnas.Tabla derivada en FROM.

La misma pregunta, dos formas de pensarla

Con IN

SELECT nombre
FROM clientes
WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
);

“Clientes cuyo id aparece en la lista de ventas.”

Con JOIN

SELECT DISTINCT c.nombre
FROM clientes AS c
INNER JOIN ventas AS v
    ON v.id_cliente = c.id_cliente;

“Unir clientes con ventas y conservar los que coinciden.”

Criterio: no buscamos una herramienta “ganadora”. Elegimos la formulación que represente con claridad la pregunta, sea correcta para los datos y resulte mantenible.
13 · Problemas que conviene detectar rápido

Errores frecuentes

1. Usar = con una subconsulta que devuelve varias filas

Incorrecto

WHERE id_cliente = (
    SELECT id_cliente
    FROM ventas
)

Si devuelve una lista

WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
)

2. Olvidar el alias de una tabla derivada

SELECT *
FROM (
    SELECT id_cliente, COUNT(*) AS cantidad
    FROM ventas
    GROUP BY id_cliente
) AS resumen;

3. No considerar NULL con NOT IN

Si la lista devuelta puede contener NULL, revisar la lógica y considerar NOT EXISTS cuando la pregunta sea de ausencia de relaciones.

4. Confundir una correlacionada con una independiente

Si la subconsulta utiliza un alias definido en la consulta exterior, existe correlación. Probarla sola sin reemplazar esa referencia no tendrá sentido.

5. Crear una subconsulta porque sí

Una consulta anidada no es automáticamente “más avanzada” ni “mejor”. Si un JOIN o un GROUP BY expresa el problema con mayor claridad, puede ser preferible.

14 · Cómo encarar un ejercicio

Método de resolución recomendado

1. Leer qué debe mostrar la consulta externa.Columnas finales y filas esperadas.
2. Detectar si hace falta un dato intermedio.Promedio, máximo, lista de ids, existencia, resumen por grupo, etc.
3. Escribir primero la consulta interna.Cuando sea independiente, ejecutarla sola y observar su resultado.
4. Clasificar lo que devuelve.¿Un valor, una lista, una matriz/tabla o simplemente existencia?
5. Elegir el operador correcto.=, IN, ANY, ALL, EXISTS…
6. Integrar y verificar.Leer la consulta completa en castellano y comprobar que responde exactamente a la pregunta.
Un hábito que evita muchos errores: antes de insertar una subconsulta dentro de otra, preguntarse “¿qué filas y columnas devuelve?”. Esa respuesta determina gran parte de la sintaxis que viene después.
15 · Para llevarse de la unidad

La forma del resultado manda

  • Una subconsulta es un SELECT utilizado dentro de otra consulta.
  • Una escalar devuelve un único valor.
  • Una lista devuelve una columna con varias filas.
  • Una matricial produce un resultado tabular; en FROM se utiliza como tabla derivada y necesita alias.
  • EXISTS y NOT EXISTS preguntan por existencia, no por el valor de las columnas.
  • Una correlacionada depende de datos de la consulta externa y puede, a la vez, ser escalar, de lista o matricial.
  • ANY/SOME expresa “alguno”; ALL, “todos”.
  • Subconsultas, JOINs y GROUP BY no compiten: resuelven necesidades diferentes y a veces ofrecen soluciones alternativas.
Pregunta final para cualquier ejercicio: “¿qué necesito obtener primero para poder responder después la consulta principal?”. Si esa pregunta tiene una respuesta clara, ya tenemos la puerta de entrada a la subconsulta.
