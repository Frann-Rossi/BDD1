01 · Punto de partida

Consultar no es modificar

Hasta ahora se trabajó con la estructura y con las filas. A partir de aquí, el objetivo es recuperar información sin alterar los datos almacenados.

DDL

Crea o modifica estructuras.

DML

Agrega, modifica o elimina filas.

SELECT

Consulta los datos y construye un resultado.

Idea central: una consulta SELECT puede devolver todas las filas, solo algunas, todas las columnas o una selección de ellas.
02 · Escenario común

Una tabla para todos los ejemplos

Para concentrarnos en las consultas, trabajaremos con una tabla simplificada de productos. En esta unidad no se evalúa modelado ni normalización: la intención es practicar SELECT sobre una sola tabla.

03 · Recuperar columnas

SELECT y FROM

SELECT indica qué queremos ver y FROM de qué tabla debe obtenerse.

SELECT *
FROM productos;

El asterisco representa todas las columnas. Cuando solo interesan algunas, conviene nombrarlas:

SELECT nombre, categoria, precio
FROM productos;
Buena práctica: en consultas reales suele ser preferible pedir solo las columnas que se necesitan.
04 · Hacer legible el resultado

Alias y DISTINCT

Un alias cambia el encabezado que vemos en el resultado, sin modificar el nombre real de la columna.

SELECT
    nombre AS producto,
    precio AS precio_actual
FROM productos;

DISTINCT elimina valores repetidos del resultado. Por ejemplo, permite conocer qué categorías aparecen en la tabla:

SELECT DISTINCT categoria
FROM productos
ORDER BY categoria;
05 · Elegir filas

WHERE y operadores de comparación

WHERE conserva únicamente las filas que cumplen una condición.

SELECT nombre, precio, stock
FROM productos
WHERE precio > 50000;

06 · Combinar condiciones

AND, OR y NOT

SELECT nombre, precio, stock
FROM productos
WHERE categoria = 'Audio'
  AND stock > 0;

AND exige que se cumplan ambas condiciones; OR, al menos una. NOT niega una condición.

SELECT nombre, categoria, activo
FROM productos
WHERE NOT activo = FALSE;
Atención con AND y OR: cuando se mezclan, usar paréntesis para que la intención quede clara.
07 · Condiciones frecuentes

BETWEEN, IN y LIKE

BETWEEN

Comprobar si un valor se encuentra dentro de un rango.

IN

Comparar contra una lista de valores posibles.

LIKE

Buscar patrones dentro de textos.

SELECT nombre, precio
FROM productos
WHERE precio BETWEEN 20000 AND 90000;

SELECT nombre, categoria
FROM productos
WHERE categoria IN ('Audio', 'Periféricos');

SELECT nombre
FROM productos
WHERE nombre LIKE '%USB%';

En LIKE, % representa cero o más caracteres y _ representa exactamente un carácter.

08 · Ausencia de dato

NULL no es lo mismo que una cadena vacía

NULL representa la ausencia de un valor conocido. En cambio, '' es un valor de texto que sí existe, pero contiene cero caracteres. Visualmente ambos pueden parecer “vacíos”, pero para MySQL son situaciones diferentes.

NULL

No conocemos el dato, no fue informado o no corresponde. Se consulta con IS NULL o IS NOT NULL.

'' · cadena vacía

El dato existe como texto, pero su longitud es cero. Puede compararse con = ''.

Ver la diferencia sobre los mismos datos

En el script de práctica, Cable HDMI 2m tiene descripcion = NULL, mientras que Adaptador USB-C tiene una descripción guardada como cadena vacía ''.

-- Productos cuya descripción no tiene un valor conocido
SELECT nombre, descripcion
FROM productos
WHERE descripcion IS NULL;

-- Productos cuya descripción existe, pero es una cadena vacía
SELECT nombre, descripcion
FROM productos
WHERE descripcion = '';
Impacto directo: las dos consultas no devuelven las mismas filas. Por eso no conviene usar NULL y '' como si fueran sinónimos.

También cambia el resultado de COALESCE

COALESCE() reemplaza valores NULL, pero no considera una cadena vacía como ausencia de valor.

SELECT nombre,
       COALESCE(descripcion, 'Sin descripción') AS detalle
FROM productos
WHERE nombre IN ('Cable HDMI 2m', 'Adaptador USB-C');
ProductoValor almacenadoResultado de COALESCE
Cable HDMI 2mNULLSin descripción
Adaptador USB-C''Cadena vacía: sigue viéndose en blanco
Otra consecuencia útil: una columna VARCHAR NOT NULL impide guardar NULL, pero por sí sola no impide guardar ''. Si el negocio exige texto real, esa regla debe controlarse además con una restricción apropiada o desde la aplicación.

¿Y si para el negocio quiero encontrar ambos casos?

SELECT nombre, descripcion
FROM productos
WHERE descripcion IS NULL
   OR descripcion = '';

Esta consulta reúne ambos casos porque la regla del negocio los está tratando como “sin descripción útil”, aunque internamente sigan siendo valores distintos.

No escribir: descripcion = NULL. Para preguntar por ausencia de valor se utiliza IS NULL.
09 · Presentar resultados

ORDER BY, LIMIT y OFFSET

ORDER BY establece el orden del resultado, LIMIT indica cuántas filas devolver y OFFSET cuántas filas omitir antes de comenzar a mostrar.

SELECT nombre, precio
FROM productos
ORDER BY precio DESC
LIMIT 5;

ASC ordena de menor a mayor y es el valor por defecto. DESC invierte el orden. En este ejemplo se devuelven solamente las primeras cinco filas del resultado ya ordenado.

Desplazar el punto de inicio con OFFSET

SELECT id_producto, nombre, precio
FROM productos
ORDER BY precio DESC, id_producto ASC
LIMIT 5 OFFSET 5;

Esta consulta omite las primeras cinco filas y devuelve las cinco siguientes. Es la idea básica de una paginación: una primera página podría usar LIMIT 5 OFFSET 0, la segunda LIMIT 5 OFFSET 5 y la tercera LIMIT 5 OFFSET 10.

Ordenar antes de paginar: una tabla no posee un orden natural garantizado. Para que las páginas sean previsibles, conviene utilizar ORDER BY. Si puede haber empates, agregar un criterio adicional y único —por ejemplo id_producto— ayuda a obtener un orden estable.
Otra sintaxis que admite MySQL
MySQL también permite escribir LIMIT 5, 5, donde el primer número es el desplazamiento y el segundo la cantidad. En la materia utilizaremos preferentemente LIMIT cantidad OFFSET desplazamiento porque resulta más explícito al leerlo.
10 · Pequeñas herramientas útiles

Funciones que vale la pena conocer

No hace falta memorizar decenas de funciones. Estas pocas aparecen constantemente y permiten construir resultados más útiles.

Texto

CONCAT(), UPPER(), LOWER().

NULL

COALESCE() e IFNULL().

Fechas

CURDATE(), NOW(), DATE(), DATEDIFF(), YEAR(), MONTH().

SELECT CONCAT(nombre, ' - ', marca) AS producto_marca
FROM productos;

SELECT nombre, COALESCE(descripcion, 'Sin descripción') AS descripcion
FROM productos;

SELECT nombre, DATEDIFF(CURDATE(), fecha_alta) AS dias_en_catalogo
FROM productos;

SELECT nombre, YEAR(fecha_alta) AS anio_alta, MONTH(fecha_alta) AS mes_alta
FROM productos;
COALESCE e IFNULL: ¿son iguales?
IFNULL(valor, reemplazo) es una función muy usada en MySQL y recibe dos argumentos. COALESCE(a, b, c, ...) devuelve el primer valor que no sea NULL y forma parte del estándar SQL. Para casos simples ambos pueden resolver una necesidad similar.
11 · Combinar lo aprendido

Una consulta completa, pero todavía simple

SELECT
    nombre AS producto,
    marca,
    precio,
    COALESCE(descripcion, 'Sin descripción') AS detalle
FROM productos
WHERE activo = TRUE
  AND categoria IN ('Audio', 'Periféricos')
  AND precio BETWEEN 20000 AND 100000
ORDER BY precio DESC
LIMIT 5;

La consulta sigue trabajando con una sola tabla. Los JOINs aparecerán en la Unidad 3, cuando necesitemos combinar información que se encuentra distribuida en tablas distintas.

12 · Errores frecuentes

Qué conviene revisar

  • No confundir = con IS NULL.
  • Usar comillas para valores de texto y fechas.
  • Recordar que BETWEEN incluye los extremos.
  • Usar paréntesis cuando se mezclan AND y OR.
  • No agregar ORDER BY si el orden del resultado no importa.
  • Si se utiliza OFFSET para paginar, acompañarlo con un ORDER BY suficientemente estable.
  • No usar funciones de agregación todavía: corresponden a la Unidad 4.
13 · Síntesis

Con qué idea quedarse

SELECT construye un resultado. Elegimos columnas, filtramos filas, transformamos algunos valores, ordenamos y, cuando hace falta, limitamos cuántas filas queremos ver.

Secuencia mental útil: ¿qué columnas necesito?, ¿de qué tabla?, ¿qué filas cumplen la condición?, ¿cómo quiero presentar el resultado?
