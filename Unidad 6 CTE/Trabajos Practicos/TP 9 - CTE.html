TP 9 · Unidad 6 · MySQL 8

Common Table Expressions: resolver por etapas y dar nombre a los resultados

El objetivo no es reemplazar todas las consultas por CTE. La práctica busca reconocer cuándo un resultado intermedio con nombre mejora la claridad y permite organizar una solución en bloques.

01 · Consigna general

¿Qué debe resolverse?

Resolver los ejercicios utilizando MySQL 8. Cuando la consigna indique una CTE, la solución debe utilizar WITH aunque el mismo resultado pudiera obtenerse con una consulta directa o con una subconsulta.

  • Probar primero el SELECT que formará el resultado intermedio.
  • Elegir nombres de CTE que describan su contenido.
  • Usar alias claros en las tablas.
  • Evitar repetir un cálculo si puede quedar definido una sola vez en una CTE.
  • No utilizar CTE recursivas en este trabajo práctico.
Idea de trabajo: en varios ejercicios conviene resolver primero la CTE sola, observar qué filas produce y recién después escribir la consulta principal.
02 · Base de trabajo

Continuamos con tienda_subconsultas

Utilizar la misma base del TP de Subconsultas para concentrarnos en la nueva herramienta sin cambiar de contexto.

Crear y cargar la base 
DROP DATABASE IF EXISTS tienda_subconsultas;
CREATE DATABASE tienda_subconsultas;
USE tienda_subconsultas;

CREATE TABLE clientes (
    id_cliente INT PRIMARY KEY,
    nombre VARCHAR(80) NOT NULL,
    ciudad VARCHAR(80) NOT NULL,
    edad INT NOT NULL
);

CREATE TABLE productos (
    id_producto INT PRIMARY KEY,
    nombre VARCHAR(80) NOT NULL,
    categoria VARCHAR(80) NOT NULL,
    precio DECIMAL(10,2) NOT NULL
);

CREATE TABLE ventas (
    id_venta INT PRIMARY KEY,
    id_cliente INT NOT NULL,
    fecha DATE NOT NULL,
    FOREIGN KEY (id_cliente) REFERENCES clientes(id_cliente)
);

CREATE TABLE detalle_ventas (
    id_detalle INT PRIMARY KEY,
    id_venta INT NOT NULL,
    id_producto INT NOT NULL,
    cantidad INT NOT NULL,
    precio_unitario DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (id_venta) REFERENCES ventas(id_venta),
    FOREIGN KEY (id_producto) REFERENCES productos(id_producto)
);

03 · Primer contacto

Ejercicio 1 — Productos costosos

Resolver

Crear una CTE llamada productos_costosos que contenga los productos cuyo precio sea igual o superior a 20.000.

Desde la consulta principal mostrar id_producto, nombre, categoria y precio, ordenados de mayor a menor precio.

Pista

La CTE necesita solamente un SELECT sobre productos con un filtro. Luego el SELECT principal consulta el nombre de la CTE.

04 · CTE con agregación

Ejercicio 2 — Resumen de categorías

Resolver

Crear una CTE llamada resumen_categorias que calcule, para cada categoría, la cantidad de productos y el precio promedio.

Desde la consulta principal mostrar únicamente las categorías cuyo precio promedio sea superior a 30.000, ordenadas de mayor a menor promedio.

05 · CTE + JOIN

Ejercicio 3 — Productos y promedio de su categoría

Resolver

Crear una CTE llamada promedios_categoria con el precio promedio de cada categoría.

Luego unirla con productos y mostrar nombre, categoria, precio y promedio_categoria de todos los productos.

Objetivo: practicar cómo una CTE participa de un JOIN. Todavía no hace falta filtrar por encima o por debajo del promedio.
06 · Resultado resumido por entidad

Ejercicio 4 — Cantidad de ventas por cliente

Resolver

Crear una CTE llamada ventas_por_cliente que calcule cuántas ventas registró cada id_cliente.

Desde la consulta principal unir ese resultado con clientes y mostrar solamente los clientes que sí tienen ventas, con su nombre y cantidad.

07 · Reescribir un problema conocido

Ejercicio 5 — Productos por encima del promedio de su categoría

Resolver

Crear una CTE con el promedio de precio de cada categoría.

Mostrar los productos cuyo precio sea mayor que el promedio correspondiente a su propia categoría.

Condición: resolver mediante CTE + JOIN. No utilizar la subconsulta correlacionada del TP anterior.

Recordar la lógica del TP anterior

Antes resolvimos: “para cada producto, calcular el promedio de su categoría”. Ahora buscamos producir primero todos los promedios y después relacionarlos con los productos.

08 · Dos resultados independientes

Ejercicio 6 — Clientes de Mar del Plata y cantidad de ventas

Resolver

Definir dos CTE dentro de la misma sentencia:

  1. clientes_mdp: clientes cuya ciudad sea Mar del Plata.
  2. ventas_por_cliente: cantidad de ventas por cliente.

Desde la consulta principal mostrar todos los clientes de Mar del Plata con su cantidad de ventas. Los que no tengan ventas deben aparecer con 0.

Atención: hay que conservar también a los clientes sin coincidencias en la CTE de ventas.
09 · CTE encadenadas

Ejercicio 7 — Total gastado por cliente en dos etapas

Resolver

Construir la solución mediante dos CTE:

  1. totales_venta: calcular el importe total de cada venta a partir de detalle_ventas.
  2. totales_cliente: utilizar totales_venta junto con ventas para acumular cuánto gastó cada cliente.

La consulta principal debe mostrar nombre del cliente y total gastado, ordenado de mayor a menor.

Pista conceptual

La segunda CTE puede utilizar directamente el nombre de la primera porque fue definida antes.

10 · Reutilizar el mismo resultado

Ejercicio 8 — Clientes que gastaron más que el promedio

Resolver

Crear una CTE totales_cliente que calcule el total gastado por cada cliente que realizó compras.

Mostrar los clientes cuyo total gastado sea mayor que el promedio de los totales calculados.

Condición: utilizar la CTE tanto para obtener el total de cada cliente como para calcular el promedio general de esos totales.

11 · Integrador

Ejercicio 9 — Diseñar la solución por bloques

Resolver y justificar

Mostrar para cada categoría:

  1. cantidad de productos;
  2. precio promedio;
  3. cantidad total de unidades vendidas de productos de esa categoría.

Deben aparecer también las categorías cuyos productos nunca fueron vendidos, con cantidad vendida igual a 0.

Condición: utilizar al menos una CTE. Antes de escribir el SQL, indicar en una frase qué resultado intermedio conviene calcular primero.

No usar CTE “porque sí”: el ejercicio busca que el bloque elegido tenga sentido y simplifique la lectura de la consulta principal.
12 · Antes de entregar

Lista de revisión

  • ¿Escribí un único WITH cuando definí varias CTE?
  • ¿Separé las CTE con comas?
  • ¿La consulta principal forma parte de la misma sentencia?
  • ¿El nombre de cada CTE describe el resultado que contiene?
  • ¿Puedo explicar qué filas produce cada CTE antes de usarla?
  • ¿Una CTE posterior utiliza solamente CTE definidas antes?
  • ¿Usé LEFT JOIN cuando necesitaba conservar filas sin coincidencia?
  • ¿Evité CTE recursivas, que no forman parte de esta práctica?
